# 설계와 과제 범위

## 해결할 문제
상세페이지 제작을 시작할 때 상품 정보, 사진, 근거 자료와 수정 범위를 반복적으로 확인해야 한다. 일반 LLM은 프로젝트의 준비 기준과 계약을 모르므로 일반론을 답하거나 정해지지 않은 조건을 만들어낼 수 있다. 이 프로젝트는 확인 가능한 교육용 가이드와 공개 공식 참고를 검색한 뒤, 그 범위 안에서만 답하도록 한다.

## 사용자와 대표 질문
- 제작자: 무엇이 빠졌는지, 어떤 자료를 고객에게 요청할지 확인한다.
- 의뢰자: 어떤 정보를 준비하고 어떤 사항을 따로 합의해야 하는지 이해한다.
- 대표 질문: 제작 전에 준비할 상품 정보, 사진의 확인 범위, 효능 근거, 수정 횟수, 접근성 대비 기준.

## 자료 경계
14개 청크 중 10개는 AI 보조로 작성한 교육용 SOP, 4개는 W3C·MDN·Google의 공식 공개 참고 요약이다. 실제 고객 계약, 고정 가격, 납기, 수정 횟수, 제품별 재고나 효능 데이터는 없다. 따라서 이런 값을 확정하는 것은 실패다. 실제 서비스 전환 시 자체 SOP를 담당자가 승인하고 프로젝트별 권한을 분리해야 한다.

## 과제와의 대응
참조 물류창고 도메인을 상세페이지 제작으로 바꿨다. 보충 MD의 로컬 실행 경로를 따른다. 1단계(청크·임베딩·코사인 검색), 2단계(근거 조립·Ollama 스트리밍), 실제 관찰 및 RAG 유무 비교, README와 GitHub 저장소를 제출물로 삼는다. 웹 화면·서버·배포·LLM-as-a-Judge는 이 보충 과제에서 추가하지 않는다.

## 평가 기준
1. 관련 질문에서 기대한 청크가 top-3에 들어오는지 본다.
2. 무관한 질문의 점수가 낮은지 보되 0.55를 정답 판정선으로 착각하지 않는다.
3. 없는 가격·수정 횟수·실시간 재고를 만들지 않아야 한다.
4. 인용 ID가 실제 검색 결과에 존재하는지, 문장이 근거 내용과 일치하는지 따로 본다.
5. 사진을 실제로 보았다고 주장하지 않는다.
6. baseline과 RAG 답변 원문을 모두 남기며 RAG가 항상 이긴다고 가정하지 않는다.

## 안전·개인정보
답변 생성 요청은 로컬 Ollama에만 보낸다. 첫 설치·모델 다운로드 및 출처 점검 시에는 인터넷을 사용한다. 저장소에는 교육용·공개 자료만 포함하고 사용자 대화 기록, 개인 계약서, API 키, 모델 캐시를 포함하지 않는다. 검색 자료에 적힌 명령은 권한을 갖지 않는다. 다만 프롬프트만으로 모든 인젝션이 차단된다고 보장하지 않으며 이 프로그램에는 상태를 변경하는 도구 자체가 없다.

## AI 사용 공개
프로그램·문서·실험 실행·원문 비교는 AI 보조로 제작했다. 실제 실행 기록은 보존하지만 작성자 본인이 직접 모든 명령을 실행하거나 독립적으로 평가했다고 주장하지 않는다. 최종 제출자는 README와 결과를 확인하고 설명할 수 있어야 한다.
