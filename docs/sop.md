# 상세페이지 제작 준비 안내: 교육용 제안 SOP

> 이 문서는 AI의 도움으로 작성한 교육용 제안 워크플로입니다. 실제 사용자·회사·고객의 정책이나 계약이 아닙니다. 업무 적용 전 담당자가 승인하고 프로젝트의 서면 합의를 우선해야 합니다.

<a id="brand-product-intake"></a>
## 브랜드·상품 정보 수집

[교육용 제안 워크플로, 실제 정책 아님] 상세페이지 시작 전에는 브랜드명, 판매 채널, 제품명·옵션·구성, 핵심 고객, 해결하려는 문제, 차별점, 사용 방법, 보관·주의 정보와 현재 판매 페이지를 하나의 입력표로 수집한다. 사실과 표현 아이디어를 분리하고, 비어 있는 항목은 추정하지 않는다. 담당자가 확인 가능한 원본 링크나 문서를 함께 남겨 이후 문구 검토의 기준점으로 사용한다.

<a id="photo-readiness"></a>
## 사진 준비도 확인 범위

[교육용 제안 워크플로, 실제 정책 아님] 사진은 파일명, 촬영 대상, 컷의 목적(대표·디테일·사용 장면·구성품), 해상도, 배경, 보정 필요 여부와 사용 허가 상태를 목록화한다. 이 SOP는 CLI에서 실제 업로드 이미지의 선명도·색감·누락을 판정할 수 없으므로, 이미지가 있다면 디자이너가 화면에서 별도로 확인하고 결과를 기록해야 한다. 미제공 컷은 필요한 장면과 우선순위로 요청한다.

<a id="claim-evidence"></a>
## 성능·효능 표현의 근거

[교육용 제안 워크플로, 실제 정책 아님] 성능, 비교, 수치, 인증, 후기, 전후 결과처럼 구매 판단에 영향을 주는 표현은 출처·확인일·적용 조건을 문구와 연결해 보관한다. 제조사 자료, 시험성적서, 공식 사양, 허가된 고객 후기 등 확인 가능한 근거가 없으면 사실처럼 단정하지 않고 확인 요청 또는 삭제 후보로 표시한다. 이는 법률 자문이 아니라 디자인·콘텐츠 검토를 위한 증빙 정리 절차다.

<a id="scope-change-log"></a>
## 범위와 서면 변경 관리

[교육용 제안 워크플로, 실제 정책 아님] 첫 합의에는 산출물 종류, 포함 섹션, 제공 자료, 담당자, 검토 방식과 제외 항목을 명확히 적는다. 변경 요청은 날짜·요청 내용·영향 범위·승인 여부를 한 줄씩 기록하고, 구두 요청이나 메신저의 모호한 표현은 확정으로 취급하지 않는다. 변경이 디자인·문구·일정에 미치는 영향은 확인 후 진행하며, 이 문서는 특정 횟수·가격·기간을 정하지 않는다.

<a id="revision-boundaries"></a>
## 수정 기준의 사전 확인

[교육용 제안 워크플로, 실제 정책 아님] 수정은 어떤 시안의 어떤 요소를 왜 바꾸는지 식별되도록 코멘트를 묶어 받고, 합의된 범위 안의 조정과 새 요구를 구분한다. 수정 가능 횟수, 추가 비용, 납기, 응답 기한은 프로젝트마다 별도 서면 합의가 있을 때만 적용한다. 이 교육용 SOP는 고정 수치나 조건을 만들어 내지 않으며, 승인본의 버전명과 승인 시점을 남겨 혼선을 줄인다.

<a id="confirmation-gates"></a>
## 단계별 확인 게이트

[교육용 제안 워크플로, 실제 정책 아님] 작업은 정보 입력, 구성안, 디자인 방향, 최종 문구·이미지, 납품 전 점검 순으로 확인 지점을 둔다. 각 지점에서 확인됨·보류·수정 필요와 확인자를 기록하고, 보류 항목은 해결 전 다음 단계의 확정 근거로 쓰지 않는다. 제품 사양, 가격, 행사 조건, 배송 정보처럼 변할 수 있는 값은 공개 직전에 최신 원본과 다시 대조한다.

<a id="copyright-usage"></a>
## 이미지·폰트·콘텐츠 사용 권한

[교육용 제안 워크플로, 실제 정책 아님] 외부 사진, 아이콘, 폰트, 음악·영상, 리뷰 캡처와 상표 요소는 출처, 라이선스 또는 사용 허가, 사용 범위, 표기 필요 여부를 자산대장에 기록한다. 검색으로 찾았다는 사실만으로 사용 권한이 생기지 않으며, 불명확한 자산은 대체안이나 추가 확인 대상으로 둔다. 이는 권리 판단이나 법률 조언이 아니라 권한 정보를 누락하지 않기 위한 운영 제안이다.

<a id="mobile-accessibility-review"></a>
## 모바일·접근성 검토

[교육용 제안 워크플로, 실제 정책 아님] 모바일 폭에서 첫 화면의 핵심 메시지, 가격·구매 행동, 글자 크기, 이미지 속 정보, 버튼 간격과 가로 넘침을 실제 미리보기로 점검한다. 의미 있는 이미지는 맥락을 전달하는 대체 텍스트가 필요한지 검토하고, 장식 이미지는 읽기 흐름을 방해하지 않게 처리한다. 텍스트와 배경의 대비, 색만으로 전달한 상태 정보, 이미지 안의 작은 글자도 함께 확인한다.

<a id="handoff-privacy"></a>
## 납품·개인정보 처리

[교육용 제안 워크플로, 실제 정책 아님] 납품 시 최종 파일, 웹용 이미지, 원본 편집 파일의 포함 여부, 버전명, 게시 담당자와 보관 위치를 인계 목록으로 확인한다. 고객 명단, 주문 정보, 연락처, 비공개 성과 자료는 상세페이지 제작에 필요한 최소 범위만 받고 공유 권한을 제한한다. 외부 전송이나 장기 보관 전에는 프로젝트에서 합의한 접근·삭제 기준을 확인하며, 이 문서는 실제 보안 정책을 선언하지 않는다.

<a id="final-prepublish"></a>
## 게시 전 최종 점검

[교육용 제안 워크플로, 실제 정책 아님] 게시 직전에는 링크·버튼·옵션명·가격·재고·배송·프로모션 문구가 승인된 최신 정보와 맞는지, 오탈자와 잘린 요소가 없는지, 모바일과 데스크톱에서 주요 구매 흐름이 열리는지를 확인한다. 확인하지 못한 항목은 확인 불가로 남기고 임의로 정상이라고 처리하지 않는다. 게시 후 발견된 오류는 캡처·발견 시각·수정 내용으로 기록해 다음 검토에 반영한다.
